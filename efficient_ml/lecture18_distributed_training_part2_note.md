## 1. 混合平行與自動平行化

### 1.1 複習：三種平行的取捨

[▶ 01:00](https://youtu.be/ZSZQL0q8eYY?t=60)

| | **資料平行** | **管線平行** | **張量平行** |
|---|---|---|---|
| 切什麼 | 資料 | 按層切模型 | 按張量切模型 |
| 模型副本 | $N$ 份 | 1 份 | 1 份 |
| 利用率 | 高 | **低**（快的層要等慢的層） | 高 |
| 記憶體 | **高**（可用 ZeRO / FSDP 改善） | 低 | 低 |
| 通訊 | 低 | 中 | **高** |

**InfiniBand 的速度**：EDR 100 Gb/s、HDR 200 Gb/s、NDR 400 Gb/s。

### 1.2 混合起來用

[▶ 03:00](https://youtu.be/ZSZQL0q8eYY?t=180)

| 組合 | 外層 | 內層 |
|---|---|---|
| **2D：資料 + 管線**（DeepSpeed） | 資料平行：兩組 GPU 吃不同資料 | 每組 2 張 GPU 做管線平行 |
| **2D：管線 + 張量**（Megatron-LM） | 管線平行 | 張量平行 |
| **3D：資料 + 管線 + 張量**（DeepSpeed） | | |

【口頭】[▶ 04:00](https://youtu.be/ZSZQL0q8eYY?t=240) 3D 的圖裡，**同顏色代表同一台伺服器上的 GPU**。同一台伺服器內通訊比較快，所以把**通訊量最大的張量平行**放在同一台伺服器裡。

### 1.3 怎麼找最好的平行策略？Alpa

[▶ 05:00](https://youtu.be/ZSZQL0q8eYY?t=300)

- **模型太大放不進一張 GPU** → 用管線平行切模型。
- **單一層就太大** → 用張量平行切那一層。
- 但組合起來的**設計空間非常大**，手動設定很難。

**兩種平行**：[▶ 06:00](https://youtu.be/ZSZQL0q8eYY?t=360)

| | **Inter-operator（運算子之間）** | **Intra-operator（運算子內部）** |
|---|---|---|
| 對應 | 管線平行 | 張量平行、資料平行 |
| 決定什麼 | 哪幾層分在同一組 | 每個運算怎麼切（橫切、直切、複製） |

**Inter-op 要注意平衡**：[▶ 07:00](https://youtu.be/ZSZQL0q8eYY?t=420) 【口頭】管線的每個 stage 工作量要差不多。如果某個 stage 很小，它馬上做完就只能閒著等別人（跟計算機結構課學過的管線一樣）。

**Intra-op 的選擇**：[▶ 08:00](https://youtu.be/ZSZQL0q8eYY?t=480) 以矩陣乘法 $C = A\times B$（$A$ 是輸入、$B$ 是權重）為例：

| 策略 | 怎麼切 |
|---|---|
| **資料平行** | 每個 worker 有同樣的 $B$，各自處理一部分的 $A$ |
| **運算子平行（type 1）** | 把 $B$ 直切 |
| **運算子平行（type 2）** | 把 $B$ 橫切 → 結果要加 All-Reduce 的成本 |

**Alpa 的做法**：[▶ 09:00](https://youtu.be/ZSZQL0q8eYY?t=540) 一個統一的分散式訓練編譯器，**分層搜尋**：

1. 先決定 inter-op（怎麼切成 stage）。
2. 再決定每個 stage 的 intra-op（每個運算怎麼切）。
3. 最後做執行時的編排。

【投影片補充】inter-op 用動態規劃（Dynamic Programming）、intra-op 用線性規劃求解。

**結果**：自動搜尋、不用手動設定，就能**追上專門手動調過的系統**，比手動基準**最多快 8 倍**。

## 2. ⭐ 分散式訓練的頻寬與延遲瓶頸

### 2.1 通訊是規模化的關鍵瓶頸

[▶ 10:00](https://youtu.be/ZSZQL0q8eYY?t=600)

```
資料更多 → 模型更大 → 計算和記憶體更多 → 要分散式訓練 → 通訊更多
```

【口頭】深度學習的成功靠的是**規模化**，而通訊是規模化的主要瓶頸之一。

參數伺服器的 **Push & Sum** 要同步，而且頻率很高，worker 一多就卡住。[▶ 11:00](https://youtu.be/ZSZQL0q8eYY?t=660)

### 2.2 要多少頻寬才不會讓 GPU 餓肚子？

[▶ 12:00](https://youtu.be/ZSZQL0q8eYY?t=720)

| 模型 | 參數（M） | 迭代時間（A6000，bs=32，ms） | 需要的頻寬（FP32 梯度，Gb/s） |
|---|---|---|---|
| ResNet-18 | 11.69 | 20 | 18.7 |
| ResNet-50 | 25.75 | 63 | 13.1 |
| Swin-Tiny | 28.10 | 119 | 7.6 |
| Swin-Base | 88.01 | 290 | 9.7 |
| Swin-Large | 196.75 | 523 | 12.0 |

⚠️ 逐字稿缺字：字幕寫「6,000 GPU」，依投影片應為 **A6000** GPU。

**算法**（⭐ 以 ResNet-18 為例）：[▶ 13:00](https://youtu.be/ZSZQL0q8eYY?t=780)

1. 梯度維度 = 權重維度 = 11.69M 個數。
2. FP32，每個 4 bytes：$11.69\times10^6\times4 = 46.76\ \text{MB}$。
3. 每 20 ms 要送一次：$46.76\ \text{MB} / 0.02\ \text{s} = 2338\ \text{MB/s}$。
4. 1 byte = 8 bit：$2338\times8 \approx 18.7\ \text{Gb/s}$。

→ 這還只是視覺模型、單向傳一次。模型更大、節點更多（All-Reduce）就要更多。

### 2.3 擴展性比理想差很多

[▶ 14:00](https://youtu.be/ZSZQL0q8eYY?t=840)

- **理想**：250 張 GPU 快 250 倍。
- **實際**（20 Gbps 乙太網路）：ResNet-152 少很多，**AlexNet 更差**。
- 【口頭】AlexNet 參數多，要送的梯度更多，所以擴展性更差。

⚠️ 待確認：教授口頭說 AlexNet「有 2.4 億個參數」，但投影片上 AlexNet 的梯度大小是 232.56 MB（約 5800 萬個 FP32 數），可能是把 MB 講成參數數量。

**木桶理論**：[▶ 15:00](https://youtu.be/ZSZQL0q8eYY?t=900) 【口頭】計算、記憶體頻寬、網路頻寬，**最短的那塊板決定能裝多少水**。網路是瓶頸的話，計算再強也沒用。

### 2.4 延遲也是瓶頸

[▶ 15:00](https://youtu.be/ZSZQL0q8eYY?t=900)

| 連線方式 | 頻寬 | 延遲 |
|---|---|---|
| 有線乙太網路、InfiniBand（資料中心） | 最高 100 Gb/s（【口頭】甚至 400） | 低到 **1 μs** |
| WiFi、行動網路（例如聯邦學習） | 最高約 1 Gb/s | 約 **200 ms** |

⚠️ 待確認：教授口頭說無線的延遲「約 100 ms 的數量級」，投影片寫「約 200 ms」。

**延遲對訓練速度的影響**：[▶ 16:00](https://youtu.be/ZSZQL0q8eYY?t=960)

| 情況 | 延遲 | 訓練變慢 |
|---|---|---|
| 同一個機架 | 1 μs ~ 1 ms | 不變 |
| 同一個資料中心 | 約 1 ms ~ 10 ms | 幾乎不變 |
| 家用無線 | 約 100 ms | **1.4×** |
| 跨越全世界 | 500 ms ~ 1 s | **3.5× ~ 5.8×** |

## 3. ⭐⭐ 梯度剪枝：稀疏通訊與 Deep Gradient Compression

### 3.1 兩種減少傳輸量的方法

[▶ 17:00](https://youtu.be/ZSZQL0q8eYY?t=1020)

跟模型壓縮一樣：

| 方法 | 做法 |
|---|---|
| **剪枝** | 大部分梯度設成 0，0 不用傳 |
| **量化** | 32 bit → 更低位元 |

### 3.2 稀疏通訊（Sparse Communication）

[▶ 18:00](https://youtu.be/ZSZQL0q8eYY?t=1080)

- **只送 top-k 個梯度**（依大小排序，留最大的 k 個）。
- **沒送出去的部分當作殘差（residual）留在本地累積**：

```
本地累積 Δ ← Δ + g
送出去：Δ 裡最大的 top-k 個
留下來：其餘的繼續留在 Δ
```

【口頭】[▶ 19:00](https://youtu.be/ZSZQL0q8eYY?t=1140) 跟推論時的剪枝不一樣：訓練有很多次迭代。一個 0.01 的小梯度，累積 10 次、100 次之後可能就超過門檻，就會被送出去。這叫 **error feedback（誤差回饋）**。

**結果**：[▶ 20:00](https://youtu.be/ZSZQL0q8eYY?t=1200)

- 丟掉 90% ~ 99.9% 的梯度，訓練速度提升（4 張 Titan X 上實驗）。
- **但在現代網路上會掉準確率**：ResNet-110、CIFAR-10，93.75% → 92.75%（**−1.00%**）。

### 3.3 問題出在動量（Momentum）

[▶ 21:00](https://youtu.be/ZSZQL0q8eYY?t=1260)

**動量 SGD 的複習**：

$$
u_t = m\cdot u_{t-1} + g_t,\qquad w_t = w_{t-1} - \eta\cdot u_t
$$

- $u_t$：**速度（velocity）**，是「上一次的方向打折」加上「這次的梯度」。
- $m$：**動量**，介於 0 和 1 之間。
- 【口頭】動量用來越過局部最小值、減少梯度雜訊造成的震盪，讓訓練更穩定。AlexNet、VGG、ResNet、Transformer、BERT 都用它。
- 更新權重時用的是**速度**，不是梯度本身。

**問題**：[▶ 23:00](https://youtu.be/ZSZQL0q8eYY?t=1380) 在本地**累積梯度**，再拿累積的梯度去算動量，**最佳化的方向會跑掉**：

| | 累積什麼 | 結果 |
|---|---|---|
| 原本的動量 SGD | — | 正確方向 |
| **沒有動量修正** | 累積**梯度** $g$，送出時才算動量 | 軌跡**對不上**原本的 SGD |
| ⭐ **動量修正** | 累積**速度** $u$ | 軌跡跟原本的 SGD **一樣** |

**動量修正（momentum correction）**：[▶ 25:00](https://youtu.be/ZSZQL0q8eYY?t=1500)

$$
u_t = m\cdot u_{t-1} + g_t,\qquad v_t = v_{t-1} + u_t
$$

- 本地先算好速度 $u_t$，再把**速度累積**到 $v_t$。
- 送出 $v_t$ 的 top-k 部分；沒送出去的留在 $v_t$ 繼續累積。

⭐ 關鍵一步：兩步不送、第三步才送出時，原本的動量 SGD 走的總步長就是 $u_{t} + u_{t+1} + \dots$ 的總和。所以本地累積的應該是 **$u$ 的總和**，不是 $g$ 的總和。

### 3.4 熱身訓練（Warm-up）

[▶ 27:00](https://youtu.be/ZSZQL0q8eYY?t=1620)

- 訓練初期網路**變化很快**，本地累積和過期的梯度會讓問題更嚴重。
- **學習率熱身**：一開始不用太大的學習率，慢慢加大。
- **稀疏度熱身**：[▶ 28:00](https://youtu.be/ZSZQL0q8eYY?t=1680) 一開始稀疏度低，前幾個 epoch **指數式增加**，避免稀疏度突然改變，讓 optimizer 慢慢適應。

### 3.5 Deep Gradient Compression（DGC）結果

**每個技巧的貢獻**：[▶ 28:00](https://youtu.be/ZSZQL0q8eYY?t=1680)

| 設定 | ResNet-110 / CIFAR-10 Top-1（8 GPU） | 5 層 LSTM / AN4 WER（4 GPU） |
|---|---|---|
| 基準 | 92.92% | 10.76% |
| 天真的梯度剪枝 | **不收斂** | **不收斂** |
| + 本地梯度累積 | 91.36%（−1.56） | 14.08%（+3.32） |
| + 本地累積 + **動量修正** + 本地梯度裁剪 | 92.56%（−0.36） | 12.92%（+2.16） |
| + 本地累積 + **熱身** | 91.89%（−1.03） | — |
| ⭐ **DGC（全部合起來）** | **93.28%（+0.37）** | **10.37%（−0.39）** |

- 【口頭】[▶ 29:00](https://youtu.be/ZSZQL0q8eYY?t=1740) 稀疏度 **99.9%**：一千個梯度只送一個，準確率還是追得上。
- 【投影片補充】LSTM 那邊還用了 **momentum factor masking**。
- 【口頭】[▶ 36:00](https://youtu.be/ZSZQL0q8eYY?t=2160) 教授總結時提到**梯度裁剪（gradient clipping）**也很重要。

**各種任務的壓縮率**：[▶ 30:00](https://youtu.be/ZSZQL0q8eYY?t=1800)

| 任務 | 模型 | 梯度大小 | 壓縮率 | 準確率 |
|---|---|---|---|---|
| ImageNet | AlexNet | 232.56 MB → **0.39 MB** | **597×** | Top-1 58.17% → 58.20% |
| ImageNet | VGG | 97.49 MB → **0.35 MB** | **277×** | Top-1 75.96% → 76.15% |
| 語言模型 | — | 194.68 MB → **0.42 MB** | **462×** | PPL 72.30 → 72.24 |
| 語音辨識 | — | 488.08 MB → **0.74 MB** | **608×** | WER 9.45% → 9.06% |

【投影片補充】為什麼不是 1000×？(1) 稀疏格式要存**索引**，有額外成本；(2) **bias 沒有剪枝**。

### 3.6 問題：All-Reduce 時稀疏梯度會變密

[▶ 31:00](https://youtu.be/ZSZQL0q8eYY?t=1860)

- 不同 GPU 的稀疏**位置不一樣**。
- Ring All-Reduce 時，每個節點把鄰居的梯度加進來 → **非零的位置越來越多**。
- 【口頭】[▶ 32:00](https://youtu.be/ZSZQL0q8eYY?t=1920) 如果大家的稀疏位置都一樣，加起來還是一樣稀疏；但通常是互補的，所以**越加越密**，後面幾步要傳很多非零值。

**解法**：[▶ 33:00](https://youtu.be/ZSZQL0q8eYY?t=1980)

1. **強制用同樣的稀疏位置**，或用粗粒度稀疏。會損失一點稀疏度，但我們本來就有 99.9% 的空間可以讓。
2. **在 Ring All-Reduce 中間再剪一次**。【口頭】這個還有待驗證。

## 4. 低秩梯度壓縮：PowerSGD

[▶ 34:00](https://youtu.be/ZSZQL0q8eYY?t=2040)

**動機**：解決稀疏位置不規則、越加越密的問題。

**做法**：不用細粒度剪枝，改用**低秩分解**。梯度矩陣 ≈ 兩個小矩陣相乘。

| | DGC（剪枝） | PowerSGD（低秩） |
|---|---|---|
| 稀疏位置 | 不同伺服器**不一樣** | 低秩矩陣的維度在每台伺服器**都一樣** |
| All-Reduce 後 | 越來越密 | 大小不變 |

【口頭】例子：4×4 的梯度（16 個數）分解成兩個 4×1 的矩陣，只要傳 8 個數，**不管傳幾輪都是 8 個**。

**結果**：

【投影片補充】CIFAR-10：

| 方法 | 類型 | 準確率 | 每 epoch 傳輸 | 每 batch 時間 |
|---|---|---|---|---|
| SGD | 全精度 | 94.3% | 1023 MB | 312 ms |
| Atomo | 梯度剪枝 | 92.6% | 113 MB | 948 ms |
| Signum | 梯度量化 | 93.6% | 32 MB | 301 ms |
| **PowerSGD Rank 2** | **低秩** | **94.4%** | **8 MB** | **239 ms** |

【投影片補充】WikiText-2：SGD 困惑度 91（7730 MB）、Signum 142（242 MB）、**PowerSGD Rank 4 91（64 MB）**，每 batch 300 ms → 134 ms。

- 【口頭】[▶ 35:00](https://youtu.be/ZSZQL0q8eYY?t=2100) worker 數增加時擴展性很好。低秩是非常有效的方法。

### 4.1 三種梯度剪枝的比較

| 方法 | 關鍵技巧 | 稀疏度 |
|---|---|---|
| **梯度稀疏化** | 本地梯度累積 | 低 |
| **DGC** | 動量修正、梯度裁剪、熱身 | **高（99.9%）**，準確率不掉 |
| **PowerSGD** | 改用低秩分解 | 不會越加越密 |

## 5. ⭐ 梯度量化：1-bit SGD、TernGrad

### 5.1 1-bit SGD

[▶ 37:00](https://youtu.be/ZSZQL0q8eYY?t=2220)

- 每個 32-bit 梯度跟 0 比較：大於 0 → 正，小於 0 → 負，**變成 1 bit**。
- **每一欄**有一個 32-bit 的縮放係數（$\mu_1, \mu_2, \dots$）。【口頭】縮放係數的成本分攤在整個矩陣上：只有 $n$ 個，不是 $n^2$ 個，所以很小。
- **量化誤差也在本地累積**，跟梯度剪枝的殘差一樣，下一次再補上。

### 5.2 Threshold quantization（門檻量化）

[▶ 38:00](https://youtu.be/ZSZQL0q8eYY?t=2280)

- 事先選一個門檻 $\tau$，**$\tau$ 同時是門檻也是重建值**：

$$
Q(g) = \begin{cases}+\tau & g > \tau\\ -\tau & g < -\tau\\ 0 & \text{其他}\end{cases}
$$

- 量化誤差在本地累積。
- 缺點：$\tau$ 要**靠經驗選**。

### 5.3 TernGrad

[▶ 39:00](https://youtu.be/ZSZQL0q8eYY?t=2340)

把梯度**隨機地**量化成 $\{-1, 0, +1\}$（乘上 $\max|g|$）：

$$
Q(g_i) = \max|g|\cdot\mathrm{sign}(g_i)\cdot b_i,\qquad b_i = \begin{cases}1 & \text{機率 } \dfrac{|g_i|}{\max|g|}\\ 0 & \text{其他}\end{cases}
$$

⭐ 關鍵一步：**期望值不變**，

$$
\mathbb{E}\left[Q(g_i)\right] = \max|g|\cdot\mathrm{sign}(g_i)\cdot\frac{|g_i|}{\max|g|} = \mathrm{sign}(g_i)\,|g_i| = g_i
$$

**例子**：【口頭】$\max|g| = 1.0$。

- $g = 0.9$ → 90% 機率變成 $+1$。
- $g = -0.8$ → 80% 機率變成 $-1$。

**特點**：

- 期望值不變，所以**不需要在本地累積量化誤差**，即時量化就好。
- 三值只要傳 2 bit。

### 5.4 量化的限制

[▶ 40:00](https://youtu.be/ZSZQL0q8eYY?t=2400)

| | 剪枝 | 量化 |
|---|---|---|
| 最多能省 | 可以很多（數百倍） | 32 bit → 1 bit，**最多 32 倍** |
| 規則性 | 不規則 | **很規則**，沒有不規則的問題 |

## 6. ⭐⭐ 延遲梯度更新：克服延遲瓶頸

### 6.1 頻寬好改善，延遲很難

[▶ 41:00](https://youtu.be/ZSZQL0q8eYY?t=2460)

**頻寬可以這樣改善**：

1. **梯度壓縮**：剪枝、量化（前兩節）。
2. **升級硬體**：

| 硬體 | 頻寬 |
|---|---|
| 乙太網路、家用路由器 | 100 Mbps ~ 1 Gbps |
| 光纖、伺服器交換器 | 1 ~ 25 Gbps |
| Mellanox 線材、InfiniBand | 20 ~ 400 Gbps（【口頭】現在甚至 800） |

**延遲很難改善**：[▶ 42:00](https://youtu.be/ZSZQL0q8eYY?t=2520)

1. **物理極限**：光速從上海到波士頓也要 **162 ms**，永遠打不破。
2. **訊號壅塞**：都市的辦公室和住家有很多訊號互相干擾。

### 6.2 傳統同步 SGD 被延遲卡住

[▶ 42:00](https://youtu.be/ZSZQL0q8eYY?t=2520)

```
Worker: [計算][====通訊====][計算][====通訊====][計算]...
```

- 計算和通訊**輪流做**，要等傳完才能開始下一步。
- 延遲越長，通訊那段越長，總時間越久。

【口頭】[▶ 43:00](https://youtu.be/ZSZQL0q8eYY?t=2580) 教授的比喻：這就像作業 1 交了才發作業 2、作業 2 交了才發作業 3。但有個偉大的發明叫**遲交天數（late day）**：做 Lab 2 的時候 Lab 3 已經發了，兩件事重疊。分散式訓練能不能也允許「遲交」的梯度？

### 6.3 Delayed Gradient Averaging（DGA）

**想法**：[▶ 44:00](https://youtu.be/ZSZQL0q8eYY?t=2640) 允許使用**過期（stale）的梯度**，讓**通訊和計算重疊**。

- 第 1 步送出梯度後，**不用等**，繼續做第 2、3、4 步的本地更新。
- 等到第 $1 + D$ 步，第 1 步的平均梯度終於到了，才套用。
- 只要通訊在 $D$ 步本地計算內傳完，**就不會擋住訓練**。

**演算法**：[▶ 45:00](https://youtu.be/ZSZQL0q8eYY?t=2700)

```
G = {}
for iter in 1 ... max_iters:
    g = grad(net, data)
    send(g, id=iter)
    G[iter] = g                         # 記住自己送出的梯度
    avg_g = recv(id=iter - D)           # 收到 D 步前的平均梯度
    W = W - lr * (g - G[iter-D] + avg_g)
```

**更新規則**（⭐ 修正項）：[▶ 49:00](https://youtu.be/ZSZQL0q8eYY?t=2940)

$$
w^{(i,j)} \leftarrow w^{(i,j)} - \eta\left(\underbrace{\nabla w^{(i,j)}}_{\text{自己這一步}} - \underbrace{\nabla w^{(i-D,j)}}_{\text{自己 D 步前的}} + \underbrace{\overline{\nabla w}^{(i-D)}}_{\text{大家 D 步前的平均}}\right)
$$

- 【口頭】不能只把別人的平均梯度加進來，還要**把自己 $D$ 步前的梯度踢掉**。因為自己的那份在當時已經用本地梯度更新過了，平均梯度裡也包含它，不踢掉會重複算。
- 投影片的 `G` 就是用來記住自己過去 $D$ 步的梯度。

**有沒有修正項的差別**（ResNet-18、CIFAR-10）：

| 延遲步數 $D$ | 沒有修正 | **有修正** |
|---|---|---|
| 5 | 88.7% | **89.2%** |
| 10 | 86.9% | **89.3%** |
| 15 | 85.5% | **89.0%** |
| 20 | 84.2% | **88.7%** |

沒有修正時，$D$ 越大掉越多；有修正時幾乎不受影響。

### 6.4 結果

[▶ 50:00](https://youtu.be/ZSZQL0q8eYY?t=3000)

- CIFAR、ImageNet、語言模型任務上，**加速 2 到 4 倍**。
- IID 和非 IID 資料都測了。跟 FedAvg（聯邦平均）比，DGA 加速更多、**準確率更好**。
- 【口頭】這讓我們能用**便宜的網路和邊緣裝置**做分散式訓練。

**真實世界測試：8 台 Raspberry Pi**　[▶ 51:00](https://youtu.be/ZSZQL0q8eYY?t=3060)

| 任務 | 8 個節點的加速 |
|---|---|
| 視覺 | **7.1×** |
| 語言 | **7.5×** |

（DGA 設定 K=5、D=20；FedAvg 在相同節點數下加速少很多。）

### 6.5 $D$ 要設多少？

[▶ 52:00](https://youtu.be/ZSZQL0q8eYY?t=3120)

【口頭】這是**網路延遲和準確率**之間的經驗取捨。先跑一下工作量測出每步的計算時間，就能算出最少要延遲幾步：

$$
D \ge \left\lceil\frac{\text{網路延遲}}{\text{每一步的計算時間}}\right\rceil
$$

【Q&A】[▶ 53:00](https://youtu.be/ZSZQL0q8eYY?t=3180) 有學生提問，但字幕沒錄到問題本身。教授回答：好主意，可以探索；這樣會有**兩份 state** 而不是一份，兩份 optimizer state 都要處理好。

⚠️ 逐字稿缺字：上面這個 Q&A 的問題沒被字幕錄到，看不出學生問的是什麼。

【口頭】課後教授帶大家到地下室參觀機房，看大模型是怎麼訓練的。

## 7. 一頁速查表

### 7.1 平行策略

| 項目 | 一句話 |
|---|---|
| **資料 / 管線 / 張量** | 利用率高/低/高；記憶體高/低/低；通訊低/中/高 |
| **3D 平行** | 張量平行放同一台伺服器（通訊最多） |
| **Alpa** | 先搜 inter-op（stage 切法），再搜 intra-op（每個運算的切法） |

### 7.2 頻寬與延遲

| 項目 | 公式或數字 | 關鍵一步 |
|---|---|---|
| **需要的頻寬** | $\dfrac{\text{參數數}\times4\ \text{bytes}\times8}{\text{迭代時間}}$ | ResNet-18：$\dfrac{11.69\text{M}\times32\ \text{bit}}{20\ \text{ms}} \approx 18.7\ \text{Gb/s}$ |
| **資料中心** | 100 Gb/s、1 μs | 延遲幾乎不影響 |
| **無線** | 1 Gb/s、~200 ms | 慢 1.4× |
| **跨世界** | 500 ms ~ 1 s | 慢 3.5× ~ 5.8× |
| **光速極限** | 上海 → 波士頓 162 ms | 延遲改不了 |

### 7.3 梯度壓縮

| 技術 | 公式或做法 | 關鍵一步 |
|---|---|---|
| **稀疏通訊** | 只送 top-k，其餘留在本地累積 | 小梯度累積夠大就會被送出（error feedback） |
| **動量 SGD** | $u_t = m u_{t-1} + g_t$，$w_t = w_{t-1} - \eta u_t$ | 更新用的是速度 $u$ |
| **動量修正** | 累積**速度** $v_t = v_{t-1} + u_t$，不是梯度 | 才能對上原本 SGD 的軌跡 |
| **DGC** | 動量修正 + 梯度裁剪 + 學習率與稀疏度熱身 | 99.9% 稀疏，277× ~ 608× 壓縮 |
| **PowerSGD** | 梯度 ≈ 兩個低秩矩陣相乘 | 維度固定 → All-Reduce 不會變密 |
| **1-bit SGD** | 正負號 + 每欄一個縮放係數 + 誤差累積 | 縮放係數只有 $n$ 個 |
| **TernGrad** | 以機率 $\dfrac{\vert g_i\vert}{\max\vert g\vert}$ 變成 $\pm\max\vert g\vert$ | $\mathbb{E}[Q(g_i)] = g_i$ → 不用累積誤差 |

### 7.4 延遲梯度更新

| 項目 | 公式 | 關鍵一步 |
|---|---|---|
| **DGA 更新** | $w \leftarrow w - \eta\left(\nabla w^{(i)} - \nabla w^{(i-D)} + \overline{\nabla w}^{(i-D)}\right)$ | 踢掉自己 $D$ 步前的，換成大家 $D$ 步前的平均 |
| **$D$ 的下限** | $\left\lceil\dfrac{\text{網路延遲}}{\text{每步計算時間}}\right\rceil$ | 通訊在 $D$ 步內傳完就不擋訓練 |

### 7.5 ⭐ 關鍵數字

| 數字 | 是什麼 |
|---|---|
| **8×** | Alpa 比手動基準最多快 |
| **7.6 ~ 18.7 Gb/s** | 視覺模型在 A6000 上需要的梯度頻寬 |
| **99.9%** | DGC 的梯度稀疏度 |
| **597× / 277× / 462× / 608×** | DGC 在 AlexNet / VGG / 語言模型 / 語音的壓縮率 |
| **8 MB vs 1023 MB** | PowerSGD Rank 2 vs SGD 每 epoch 傳輸（CIFAR-10） |
| **32×** | 量化最多能省的倍數 |
| **162 ms** | 光速從上海到波士頓 |
| **2 ~ 4×** | DGA 的加速 |
| **7.1× / 7.5×** | DGA 在 8 台 Raspberry Pi 上的視覺 / 語言加速 |
